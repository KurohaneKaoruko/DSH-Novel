# 作品工程与落盘约定

长篇不靠模型记忆，靠工程文件。所有写作成果统一落盘 Markdown，目录结构与命名遵守本约定，Obsidian 直接可用。

## 一、工程目录结构

```
作品根/
├── README.md            # 全量双链索引（novel_project 整理索引 维护）
├── 文风卡.md            # 文风基准（novel_style_profile 生成，成稿自动对齐）
├── 伏笔清单.md          # | 伏笔 | 铺设位置 | 发酵 | 回收位置 | 状态 |
├── 时间线.md            # | 时间 | 事件 | 参与人物 | 影响/后续 |
├── 大纲/
│   ├── 总纲.md
│   └── 第N卷-卷名.md
├── 设定集/              # 每类一文件
│   ├── _索引.md
│   ├── 世界观.md / 力量体系.md / 地理.md / 势力.md / …
├── 人物卡/              # 每人一文件
│   ├── _索引.md
│   └── 角色名.md
├── 归档/
│   └── 第NNN章-标题-归档.md
└── 正文/
    └── 第NNN章-标题.md   # 纯文本，每章一文件
```

- 章节文件名：`第001章-标题.md`，序号三位补零。
- 人物卡一个角色一个文件；设定集按类别分文件；不用大文件堆所有内容。
- `说明.md` 是初始化脚手架，不算内容文件。

## 二、双链规范（Obsidian 图谱）

- 人物卡 ↔ 人物卡：关系互链（`[[角色名]]`）。
- 人物卡 ↔ 设定集：归属/掌握互链（`[[设定集/力量体系|力量体系]]`）。
- 伏笔清单、时间线的行内提及人物、设定时用双链。
- README.md 是全量索引：章节、人物、设定、归档、追踪表全部双链（`novel_project 整理索引` 自动生成）。

## 三、每章标准闭环（长篇连载循环）

每写一章走完整循环，顺序固定：

1. **写前简报**：`novel_briefing` 从工程材料浓缩本章上下文（主线进度/本章任务/出场人物要点/活跃伏笔/相关设定/衔接要点/注意事项）。没有简报不动笔。
2. **单章成稿**：`novel_write_chapter`，传细纲 + 简报，`auto_context: true` 自动注入工程材料与文风卡；落笔即防 + lint 检查保证干净稿；`save: true` 直接落盘正文。
3. **章后归档**：`novel_archive` 更新伏笔清单、时间线，生成归档记录；人物状态变化回填人物卡，新设定回填设定集。
4. **整理索引**：`novel_project 整理索引`（定期，如每卷末）。
5. **发布前（可选）**：`novel_reader_panel` 读者团试读；上架章节 `novel_compliance` 合规体检。

断更恢复：隔了很久或新会话续写时，先读最近归档、伏笔清单与上一章结尾找回状态，再动笔。

## 四、工程操作对照

| 时机 | 工具 |
| --- | --- |
| 开新书 | `novel_project 初始化工程` |
| 有旧稿 | `novel_import` 自动分章落盘 + 逆推大纲/人物卡/设定集 |
| 定文风 | `novel_style_profile` 从基准章节生成文风卡 |
| 存稿 | `novel_project 保存章节` 或成稿工具 `save: true` |
| 查进度 | `novel_project 统计进度` |
| 全书体检 | `novel_scan_book`（跨章矛盾 + 跨章重复） |

## 五、Obsidian 协作工作流

把作品根目录（或工作区）作为 Obsidian Vault：

1. **生成**：Agent 产出章节/大纲/设定/人物卡（全部 Markdown，天然是 Obsidian 笔记）。
2. **阅读批注**：在 Obsidian 里读稿、高亮、评论；直接改字句后保存。
3. **反馈**：告诉 Agent「继续写」，它会读到你的修改（文件是同一份）。
4. **图谱**：双链构成设定网络，图谱视图检查人物/设定是否孤岛；标签与看板跟踪连载进度。
5. **迭代**：循环 1–4，人工与 AI 各取所长。

修改工程文件时的注意：保持表格结构（伏笔清单/时间线是 Markdown 表格，`novel_archive` 按行追加）；文件名遵守命名约定（工具按 `第NNN章` 序号定位最新章）；不要把多个角色合并回一个大文件。

## 任务流程

**人物卡建档**（角色设计/采访后落盘）：每个角色一个文件 `人物卡/角色名.md`，用文件工具写入。模板：

```
# 角色名
## 基本信息
（年龄/身份/外貌特征 1-2 个记忆点/出场章节）
## 性格核心
（欲望 + 恐惧 + 矛盾点；行为逻辑；一个「明知错还做」的不理性点——人味）
## 口癖与说话方式（语言指纹）
（风格：粗/雅/毒舌；口癖；句长偏好：短促/啰嗦；常用词；**绝不会说的词**——写对话前对照注入，防「所有人一个腔」）
## 动机与目标
## 关系
（双链：[[对方名]]，注明关系性质与当前状态）
## 当前状态
（以最近归档为准：伤病/位置/掌握的信息/情绪基调）
## 弧光预埋
```

写完把角色加入 `人物卡/_索引.md` 双链列表。

**设定集建档**（世界观构建后落盘）：每类设定一个文件 `设定集/类别名.md`（世界观/力量体系/地理/势力/物品/其他）。要求：力量体系必须写清等级划分、规则与**代价**（越强限制越多）；地理写层级（大陆→国家→城市→地点）；势力写阵营、实力层级、与主角的关系。类别之间与人物卡用双链互相关联。写完更新 `设定集/_索引.md`。

**世界观构建**（从零设计）：先定大框架（时代背景/超凡体系/社会结构），再定约束（力量规则与代价、禁区、稀缺资源），最后定延展点（可供后续剧情开发的空白区域）。自洽检查：体系能否支撑长篇的力量成长线、规则漏洞是否会被主角利用后崩坏。
