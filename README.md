# DSH-Novel · AI 写作

> 一个 Agent 预设，把 DeepSeek Harness 变成「AI 写小说」工作台：**30 个网文写作工具 + 完整网文创作方法论**，全部随「小说助手」预设内置、持久可用。
> 把本仓库（或 GitHub 链接）交给任意 DeepSeek Harness Agent，按 `INSTALL.md` 执行即可自动安装完成。

---

## 一、这是什么

本项目只包含一件东西——**「小说助手」Agent 预设**。它以写小说为核心，把 DSH 变成一位专业网文写作助手：

| 组件 | 类型 | 作用 |
| --- | --- | --- |
| **小说助手（novelist）** Agent 预设 | 用户 Agent 预设（持久） | ① **30 个 `novel_*` 写作工具**（内置 `novel-tools.mjs`），分两条线：<br>　· **创作单点**：润色、续写、**去 AI 味**、大纲整理/优化/续写、小说分析、拆书学习、灵感生成、世界观构建、角色设计、章节规划、场景写作、黄金三章、书名/标题、简介与梗概（含**前情提要/章末摘要**）、作品评阅、改写、对话优化、文学翻译、剧情漏洞排查、起名、文风设定、情节推演、**角色采访**（人声校准）、**平台合规体检**（过审风险）；<br>　· **长篇工程闭环**：**写前简报**（novel_briefing，从工程材料浓缩本章上下文）→ **单章成稿**（novel_write_chapter，草稿→自查→修订多稿流水线）→ **章后归档**（novel_archive，自动更新伏笔清单/时间线/人物状态）→ **作品工程**（novel_project，初始化/存稿/伏笔清单/时间线/统计进度/索引）——每章走一遍这个循环，长篇一致性不靠模型硬扛。<br>所有工具都调用当前会话模型做**真正的文本生成**，并遵守「去 AI 味写作红线」。<br>② **以写小说为核心的人设** + 完整的《网文创作方法论》提示段（黄金三章法则、爽点公式、节奏钩子、伏笔闭环、长篇连载循环、一致性守则、节奏量化参考、长篇工程、成稿流程、去 AI 味自查、Obsidian 落盘约定）；<br>③ 标准工作台：文件读写、网页检索、子代理与工作流、目标与待办、计划模式。 |

## 三、安装

### 方式一：交给 DSH 自动安装（推荐）

1. 把本仓库目录（或 GitHub 链接）交给任意 DeepSeek Harness Agent，例如：
   > “请把 DSH-Novel 项目安装到当前环境，按 INSTALL.md 执行。”
2. Agent 会按 `INSTALL.md` 完成：
   - 把 `agent-presets/novelist/` 复制到 DSH 用户预设根目录 `~/.dsh/.agent-presets/novelist`；
   - 用 `agentPresets.standingKeyFor('novelist')` 做挂载校验；
   - 完成后新建会话选择「小说助手」即可开始写作。

### 方式二：手动安装

见 `INSTALL.md` 中的逐条步骤（同一套内容，供手动执行）。

## 四、使用

- **日常写作**：新建会话 → 预设选择「**小说助手**」→ 直接对话：
  - “把这些素材整理成大纲，再规划第一卷 10 章”
  - “接着这篇正文续写 2000 字，结尾留钩子”
  - “帮我润色这段 / 拆解这段开篇学它的钩子写法”
- **长篇连载（推荐每章走一遍闭环）**：
  1. “初始化作品工程《书名》”（`novel_project`，自动建 正文/大纲/设定集/人物卡/归档/伏笔清单/时间线）
  2. “生成第 3 章的写前简报”（`novel_briefing`，汇总大纲、人物卡、活跃伏笔与上一章结尾）
  3. “按这份简报和细纲写第 3 章，写完保存”（`novel_write_chapter`，草稿→自查→修订后落盘）
  4. “归档第 3 章”（`novel_archive`，更新伏笔清单、时间线与归档记录）
  5. 下一步只需说“继续写下一章”，助手会带着全部上下文接着推进。
- **去 AI 味与质量**：
  - “把这段去一下 AI 味：……”（`novel_deai`，用于外来文本/旧稿；写作工具成稿时已按「落笔即防」产出干净稿）
  - “采访一下主角，我要校准他的说话方式”（`novel_interview`）
  - “这章按番茄的尺度做个合规体检”（`novel_compliance`，上架/过审前用）
- **让 Agent 把成果落盘**：让 Agent 把章节、大纲、设定集以 Markdown 保存到工作区，之后用 Obsidian 阅读与批注（见下节）。

## 五、搭配 Obsidian 使用

本项目非常适合搭配 **Obsidian** 一起使用：把「小说助手」的工作区（或专门的写作目录）直接作为 Obsidian 的 **Vault**。

- Agent 产出的章节、大纲、设定集、人物卡、伏笔清单全部是 Markdown 文件，天然就是 Obsidian 笔记——无需任何转换。
- 在 Obsidian 里**阅读与批注**成稿：正文排版、高亮、评论随手可加，改完后把文件放回工作区，告诉 Agent「继续写」，它会读到你的修改。
- 用**双链**把角色、地点、事件、势力互相关联，用**图谱视图**看清设定网络与伏笔脉络；用**标签**与**看板**跟踪连载进度、分卷与更新状态。
- 写作闭环：**Agent 生成 → Obsidian 阅读批注 → 反馈给 Agent → 迭代**，人工与 AI 各取所长。

## 六、说明

- **持久性**：整个项目就是一个 Agent 预设，随 `~/.dsh/.agent-presets/novelist` 持久存在——写作工具、人设、方法论全部内置，进程重启、切换会话都不影响，无需重装任何东西。
- **模型路由**：所有工具默认调用当前会话的默认模型，每个工具都支持传入 `provider` / `model` 覆盖；无默认模型时自动兜底到第一个可用提供方。
- **去 AI 味（落笔即防）**：所有写作工具的共享系统提示内置「落笔即防」规范——先想画面再动笔、写完一段扫一段、交稿前整篇快扫，成稿输出即干净稿，不做「先带 AI 味、事后去味」的二道工序；《网文创作方法论》第八节同步约定；`novel_deai` 只用于处理外来文本与旧稿。

## 七、维护

- 修改预设：编辑 `agent-presets/novelist/` 下文件，复制覆盖到 `~/.dsh/.agent-presets/novelist/`，并重新挂载校验（`agentPresets.standingKeyFor('novelist')`）。
- 卸载：删除 `~/.dsh/.agent-presets/novelist` 目录即可。
