# DSH-Novel · AI 写作

> 「小说助手」——一个 DeepSeek Harness Agent 预设：**7 个方法论 skill + 6 个确定性工具**，面向中文网络小说的长篇创作工作台。把本仓库交给任意 DSH Agent，按 `INSTALL.md` 执行即可完成安装。

---

## 核心特性

**一切正文由 Agent 亲写，工具零模型调用。** 6 个工具全部是纯代码（确定性检查、文件读写、材料组装），不含任何 LLM 子调用；模型生成的质量与过程完全可见、可干预。

### 7 个方法论 skill（按需加载）

| skill | 何时加载 |
| --- | --- |
| `novel-prose-standards` | 写/改/润色/翻译/去AI味任何正文——正文铁律 + 直出即净生成时干预 + 各任务流程 |
| `novel-ai-lexicon` | AI 高频词分级词库（约 200 条）：一级套路模板出现即改写、二级高频滥用限频、句式模板、白名单防误伤 |
| `novel-continuity` | 写前必查清单、前文衔接三锚点、归档回填、剧情漏洞排查 |
| `novel-plotting` | 总纲/卷纲/细纲/章节规划/情节推演/灵感/书名简介包装，含标准细纲模板与节奏量化标准 |
| `novel-craft` | 场景三拍、对话技法、打脸四拍、情绪曲线、角色设计与采访 |
| `novel-analysis` | 小说分析/拆书/评阅（六维评分）/模拟读者团/合规体检/起名 |
| `novel-project` | 工程目录约定、人物卡/设定集/文风卡建档模板、归档三件套格式、Obsidian 工作流 |

### 6 个工具（零模型调用）

| 工具 | 职责 |
| --- | --- |
| `novel_lint` | AI 味确定性检查：标点纪律、引号规范、禁用词、副词/极端词频次、句长均匀度、连续同句式、论文腔等 20 项规则，纯代码秒回 |
| `novel_briefing` | 写前材料组装：上一章结尾、最近归档、出场人物卡（按人名自动匹配）、伏笔清单、时间线、文风卡原文返回 |
| `novel_archive` | 归档三件套落盘：伏笔清单覆盖、时间线追加、归档记录写入 |
| `novel_project` | 工程文件操作：初始化目录、保存章节、统计进度、整理双链索引 |
| `novel_import` | 旧稿分章导入：按「第X章」标记自动拆分落盘 |
| `novel_scan_book` | 体检材料组装：最近连续或首中尾抽样选章，汇总工程材料 |

### 长篇质量机制

| 机制 | 做什么 |
| --- | --- |
| **写前材料组装** | 动笔前程序化读取工程文件（出场人物卡按本章计划人名自动匹配），设定、伏笔、上文全部摆在眼前，不靠模型记忆 |
| **衔接三锚点** | 自动携带上一章结尾原文，新章开头按场景/时间/情绪三锚点承接 |
| **文风卡** | 从基准章节提取结构化文风指纹落盘 `文风卡.md`，此后每章动笔前读取对齐，长篇文风不漂移 |
| **直出即净·生成时干预** | 写作时同步执行四项干预：细节种子（每场景 ≥3 个专有级细节）、呼吸句（3-4 句接 ≤8 字碎句）、开头轮换、禁模糊词；≥2500 字分场景分段写 |
| **确定性 lint** | 可量化规则交给代码：破折号 ≤1、引号规范、禁词表、副词与极端词频次、句式频次、句长均匀度（变异系数）、连续同句式开头、论文腔；写完必跑，硬违规清零为止 |
| **单章硬默认** | 用户未特别说明时：单章 2000–4000 字；结尾收在节拍落点上、禁止突兀截断；尽量留钩子 |
| **归档三件套** | 每章归档同步更新伏笔清单、时间线、归档记录，人物状态回填人物卡——长篇一致性靠工程文件兜底 |

## 安装

**自动安装（推荐）**：把本仓库目录（或 GitHub 链接）交给任意 DeepSeek Harness Agent：

> “请把 DSH-Novel 项目安装到当前环境，按 INSTALL.md 执行。”

Agent 会把 `novelist/` 复制到 DSH 用户预设根目录 `~/.dsh/.agent-presets/novelist`，并完成挂载校验。新建会话选择「小说助手」即可开始写作。手动安装见 `INSTALL.md`。

## 使用

**开新书**

1. “初始化作品工程《书名》”——建立全套目录（正文/大纲/设定集/人物卡/归档/伏笔清单/时间线/文风卡）
2. 写 1-2 章定稿后：“按文风卡格式从这几章提取文风卡保存”——此后每章文风自动对齐

**长篇连载（每章一个闭环）**

1. “组装第 3 章的写前材料”——`novel_briefing` 返回上一章结尾、人物卡、伏笔、文风卡等全部工程材料
2. “按材料和细纲写第 3 章”——助手亲写整章（生成时干预 + 分场景），写完自动跑 `novel_lint` 自检清零后保存到 `正文/第003章-标题.md`
3. “归档第 3 章”——助手按格式提取三件套（伏笔表/时间线行/归档记录），`novel_archive` 落盘，人物状态回填人物卡
4. 说“继续写下一章”，循环推进

**其他场景**

- **已有存稿**：“把这份旧稿导入工程”——`novel_import` 自动分章落盘，大纲/人物卡/设定集由助手按 skill 逆推建档
- **日常创作**：润色、大纲、拆书、起名、角色采访、合规体检、读者团试读——直接说，助手加载对应 skill 亲自完成；正文产出自动走 lint 自检循环
- **全书体检**：“抽 8 章扫一致性”——`novel_scan_book` 组装材料，助手按六维诊断输出问题清单（人物矛盾/时间线/设定冲突/战力/伏笔遗忘/跨章重复）
- **搭配 Obsidian**：工作区即 Vault，成稿即笔记；双链构成设定网络，图谱视图查孤岛；批注改稿后说“继续写”，助手会读到你的修改

## 维护

- **改方法论/任务流程**：编辑 `novelist/skills/` 下的 SKILL.md，复制覆盖到 `~/.dsh/.agent-presets/novelist/` 即生效
- **改工具**（lint 规则、材料组装、文件操作）：编辑 `novelist/plugins/novel-tools.mjs`
- **改人设/组合**：编辑 `novelist/agent.cordis.yml`
- 改动后重新挂载校验：`agentPresets.standingKeyFor('novelist')`
- 卸载：删除 `~/.dsh/.agent-presets/novelist` 目录
